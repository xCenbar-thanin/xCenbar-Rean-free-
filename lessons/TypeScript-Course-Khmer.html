១. TypeScript ជាអ្វី? អ្នកណាបង្កើត?

២. របៀបដំឡើងក្នុង VS Code

  1. ដំឡើង Node.js LTS (22.18+ ឬ 24) និង VS Code — VS Code គាំទ្រ TypeScript ស្រាប់ (IntelliSense, Error ពណ៌ក្រហម)
  2. Extensions ដែលមានប្រយោជន៍៖ ESLint, Prettier, Pretty TypeScript Errors (Error អានងាយ), Error Lens (Error នៅលើបន្ទាត់)
  3. បង្កើតគម្រោង ហើយដំឡើង TypeScript ក្នុងគម្រោង (មិនមែន Global)
  4. VS Code៖ Ctrl+Shift+P → TypeScript: Select TypeScript Version → Use Workspace Version
💡 Node.js រត់ .ts ដោយ «Type stripping»៖ វាលុប Type ចេញ ប៉ុន្តែ មិនពិនិត្យ Type ហើយមិនគាំទ្រ Syntax ដែលបង្កើតកូដ JavaScript ថ្មី (enum, namespace មាន Value, Parameter properties)។ erasableSyntaxOnly ធ្វើឱ្យ tsc រារាំង Syntax ទាំងនោះ។ Import ត្រូវមាន .ts៖ import { x } from "./x.ts"។

💡 ទុកឱ្យ TypeScript ទាយ (Inference) ពេលតម្លៃច្បាស់ ហើយសរសេរ Type នៅ Parameter របស់ Function និង API សាធារណៈ។ មើលក្នុងឧទាហរណ៍៖ tsc រកឃើញ Bug ២ ប៉ុន្តែ JavaScript នៅតែរត់ — បន្ទាត់ចុងក្រោយ Crash ពេលរត់ (Uncaught TypeError)។ នោះហើយជាមូលហេតុដែលត្រូវរត់ tsc ក្នុង CI។

មេរៀន ១៤Migration JS → TS, TypeScript 7, ESLint & Best Practices

  1. ដំឡើង TypeScript + tsconfig.json ជាមួយ allowJs: true, checkJs: false
  2. ប្តូរ File ម្តងមួយ .js → .ts ចាប់ពី Types/Utils (មិនពឹងលើគេ) ទៅ Routes/Components
  3. ចាប់ផ្តើមដោយ strict: true · Error ច្រើន → ជួសជុលម្តងមួយ (មិនមែន any គ្រប់កន្លែង)
  4. បន្ថែម npm run typecheck ក្នុង CI (GitHub Actions) — Merge មិនបានបើ Type ខុស
  5. typescript-eslint៖ ច្បាប់ដូចជា no-explicit-any, no-floating-promises

TypeScript 7 (Native compiler)

  • Compiler សរសេរឡើងវិញជា Go — Type-check គម្រោងធំលឿនប្រហែល 10 ដង · ដំឡើងដដែល៖ npm i -D typescript
  • strict ជា Default · Option ដែលបាន Deprecated ក្នុង 6.0 ក្លាយជា Error → ឡើង 6.0 មុន រួចទើប 7.0
  • Tooling ខ្លះដែលពឹងលើ TypeScript API (ឧ. typescript-eslint) អាចត្រូវការ @typescript/typescript6 បណ្តោះអាសន្ន
