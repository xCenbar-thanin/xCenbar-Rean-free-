១. UX/UI Design ជាអ្វី?

UX = User Experience
បទពិសោធន៍អ្នកប្រើ — តើ App ងាយប្រើ មានប្រយោជន៍ ហើយដោះស្រាយបញ្ហាពិតឬទេ? (Research, Flow, Wireframe, Testing)
UI = User Interface
ផ្ទៃប្រើប្រាស់ — អ្វីដែលអ្នកប្រើ មើលឃើញ និងចុច៖ ពណ៌ អក្សរ ប៊ូតុង Icon ប្លង់ ចលនា
💡 ឧទាហរណ៍ងាយ៖ ផ្ទះមួយ — UX គឺការរៀបចំបន្ទប់ឱ្យរស់នៅស្រួល (ផ្លូវដើរ, ទីតាំងបង្គន់, ពន្លឺ) ហើយ UI គឺពណ៌ជញ្ជាំង, គ្រឿងសង្ហារិម, កុងតាក់ភ្លើង។ ផ្ទះស្អាតតែរស់នៅលំបាក = UI ល្អ UX អាក្រក់។

ជំហានទី ១: បង្កើតគណនី Figma

  3. ប្រើក្នុង Browser បានភ្លាម ឬទាញយក Figma Desktop App (Windows/macOS) ពី figma.com/downloads

  4. (កម្រិតខ្ពស់) ភ្ជាប់ Figma MCP server ទៅ AI ក្នុង VS Code ដើម្បីឱ្យ Developer/AI អាន Design របស់អ្នកបានត្រឹមត្រូវ

Jakob's Lawអ្នកប្រើចំណាយពេលភាគច្រើនលើ App ផ្សេង ហើយរំពឹងថា App អ្នកដំណើរការដូចគ្នាLogo ខាងឆ្វេងលើ, Cart ខាងស្តាំលើ

មេរៀន ១Design Thinking & Double Diamond

ដំណើរការរចនាដែលផ្តោតលើ មនុស្ស (Human-centered)។ Design Thinking ៥ ដំណាក់កាល (Stanford d.school)៖

  1. Empathize (យល់ចិត្ត) — សង្កេត សម្ភាសន៍អ្នកប្រើពិត
  2. Define (កំណត់បញ្ហា) — សរសេរ Problem statement ឱ្យច្បាស់
  3. Ideate (បង្កើតគំនិត) — Brainstorm គំនិតច្រើន មិនទាន់វិនិច្ឆ័យ
  4. Prototype (គំរូ) — ធ្វើគំរូលឿនៗ ថោកៗ (ក្រដាស ឬ Figma)
  5. Test (សាកល្បង) — ឱ្យអ្នកប្រើពិតសាក ហើយត្រឡប់ទៅកែ (Iterate)

មើលចម្លើយ
  1. ស្វែងរក៖ Search bar + Filter (ថ្ងៃ ម៉ោង ចំនួនមនុស្ស) + បញ្ជីហាង (រូប, ឈ្មោះ, ⭐, ចម្ងាយ)។ សកម្មភាពចម្បង៖ ចុចហាង
  2. ព័ត៌មានហាង៖ រូបធំ, ម៉ោងបើក, ផែនទី, ម៉ោងទំនេរជាប៊ូតុងតូចៗ។ សកម្មភាពចម្បង៖ ប៊ូតុង «កក់តុ» នៅខាងក្រោម (ជិតមេដៃ)
  3. បញ្ជាក់៖ សង្ខេប (ហាង ថ្ងៃ ម៉ោង មនុស្ស), ឈ្មោះ/លេខទូរស័ព្ទ។ សកម្មភាពចម្បង៖ «បញ្ជាក់ការកក់» + តំណ «កែ»

Visual Hierarchy: ប៊ូតុង Primary vs Secondary

✍️ លំហាត់ ៥

មើល App ធនាគារ ឬ Delivery ដែលអ្នកប្រើរាល់ថ្ងៃ។ រកឧទាហរណ៍ Hierarchy, Proximity និង Consistency មួយៗ ហើយពន្យល់។

មើលចម្លើយគំរូ
  • Hierarchy៖ សមតុល្យគណនីអក្សរធំបំផុតនៅខាងលើ ព្រោះជាអ្វីដែលអ្នកប្រើចង់ដឹងមុនគេ។
  • Proximity៖ ឈ្មោះអ្នកទទួល និងលេខគណនីនៅជិតគ្នា ហើយឃ្លាតពីចំនួនប្រាក់ → មើលដឹងថាជាក្រុមព័ត៌មានផ្សេងគ្នា។
  • Consistency៖ ប៊ូតុង «បន្ត» ពណ៌ដដែល និងនៅទីតាំងដដែល (ខាងក្រោម) គ្រប់ជំហានផ្ទេរប្រាក់។

#Heuristicឧទាហរណ៍
1Visibility of system status — ប្រាប់ថាកំពុងមានអ្វីកើតឡើងLoading bar, «កាហ្វេនឹងរួចក្នុង ៥ នាទី»

6Recognition rather than recall — ឱ្យឃើញ មិនឱ្យចាំ«បានស្វែងរកថ្មីៗ»
7Flexibility & efficiency — ផ្លូវកាត់សម្រាប់អ្នកជំនាញ«កុម្ម៉ង់ដដែល», Shortcut
8Aesthetic & minimalist designដកព័ត៌មានមិនចាំបាច់
9Help users recover from errorsសារ Error ច្បាស់ + ដំណោះស្រាយ
10Help & documentationTooltip, FAQ, ការណែនាំខ្លី

  1. កំណត់គោលដៅ — ឧ. «តើអ្នកប្រើអាចកុម្ម៉ង់កាហ្វេបានក្រោម ១ នាទីទេ?»

✍️ លំហាត់ ១៥

អ្នកចូលរួម ៥ នាក់៖ ៣ នាក់កុម្ម៉ង់បាន ក្នុង 40s, 55s, 70s ហើយ ២ នាក់បរាជ័យ។ គណនា Success rate និងពេលមធ្យមរបស់អ្នកដែលជោគជ័យ។ តើគួរធ្វើអ្វីបន្ត?

មើលចម្លើយ

Success rate = 3 ÷ 5 = 60% · ពេលមធ្យម = (40 + 55 + 70) ÷ 3 = 55 វិនាទី។

60% ទាបពេក → មើលវីដេអូ/កំណត់ត្រាថាអ្នកបរាជ័យជាប់គាំងនៅជំហានណា (ឧ. ជ្រើស Size) កែ Design ហើយ Test ម្តងទៀតជាមួយ ៥ នាក់ថ្មី។

មេរៀន ១៦Design Handoff: ប្រគល់ Design ឱ្យ Developer

  1. ដាក់ឈ្មោះ Layer និង Frame ឱ្យច្បាស់ (Button/Primary មិនមែន Rectangle 23)
  2. ប្រើ Variables (ពណ៌ គម្លាត) និង Styles (អក្សរ ស្រមោល) — កុំសរសេរតម្លៃផ្ទាល់
  3. ប្រើ Auto Layout គ្រប់ទីកន្លែង → Developer ឃើញ Flexbox ច្បាស់
  4. ចុច Mark as ready for dev លើ Frame ដែលរួចរាល់
  5. Developer បើក Dev Mode (Shift+D) ឬ Figma for VS Code ដើម្បីមើលទំហំ ពណ៌ និង Export Asset — Designer មិនចាំបាច់សរសេរកូដទេ
