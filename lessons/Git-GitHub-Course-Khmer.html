មេរៀន ០Git និង GitHub ជាអ្វី?

Git គឺជាប្រព័ន្ធ ត្រួតពិនិត្យជំនាន់ (Version Control) ដែលចងចាំប្រវត្តិនៃរាល់ការកែ code របស់អ្នក ដូចជា "ប៊ូតុង Undo ដ៏អស្ចារ្យ" ដែលអាចត្រឡប់ទៅជំនាន់ណាក៏បាន។ GitHub គឺជា website សម្រាប់ ផ្ទុក Git repository លើអនឡាញ (ដូចជា Google Drive សម្រាប់ code) ដើម្បីបម្រុងទុក ចែករំលែក និងធ្វើការជាក្រុម។

⚠️ កុំច្រលំ៖ Git = កម្មវិធីលើកុំព្យូទ័រអ្នក។ GitHub = សេវាអនឡាញដែលប្រើ Git។ មានសេវាស្រដៀងគ្នាផ្សេងទៀតដូចជា GitLab និង Bitbucket។

👤 ប្រវត្តិ

  • Git ត្រូវបានបង្កើតដោយ Linus Torvalds (អ្នកបង្កើត Linux) នៅឆ្នាំ 2005 ដើម្បីគ្រប់គ្រង code របស់ Linux Kernel។
  • GitHub ចាប់ផ្តើមនៅឆ្នាំ 2008 ហើយក្រុមហ៊ុន Microsoft បានទិញនៅឆ្នាំ 2018។

  • ☁️ បម្រុងទុកលើ Cloud៖ កុំព្យូទ័រខូច ក៏ code មិនបាត់
  • 👥 ធ្វើការជាក្រុម៖ មនុស្សច្រើននាក់កែ project តែមួយបានដោយមិនជាន់គ្នា
  • 💼 Portfolio៖ GitHub ជាប្រវត្តិរូបការងាររបស់អ្នកអភិវឌ្ឍន៍ ហើយនិយោជកតែងតែមើល
  • 🌍 ដាក់ web ឲ្យអ្នកដទៃមើល ឥតគិតថ្លៃដោយ GitHub Pages

មេរៀន ១ដំឡើង Git និងបង្កើតគណនី GitHub

  1. ដំឡើង Git៖ ទៅ git-scm.com/downloads ជ្រើសប្រព័ន្ធរបស់អ្នក។
    Windows៖ ដំណើរការ installer ហើយចុច Next តាមលំនាំដើម (រួមមាន Git Bash និង Git Credential Manager)។
    macOS៖ វាយ xcode-select --install ឬ brew install git។
    Linux (Ubuntu/Debian)៖ sudo apt install git។
  2. ពិនិត្យការដំឡើង៖ បើក Terminal (ឬ Git Bash) ហើយវាយ git --version។ ក្នុង VS Code អាចបើក Terminal ដោយ Ctrl+`។
  3. កំណត់អត្តសញ្ញាណ (ធ្វើតែម្តង) ដូចក្នុងប្លុកខាងក្រោម។
  4. បង្កើតគណនី GitHub៖ ចូល github.com → Sign up (ប្រើអ៊ីមែលដូចដែលបានកំណត់ក្នុង Git ល្អបំផុត)។
  5. ភ្ជាប់ការចូល (Authentication)៖ ពេល git push លើកដំបូង Git Credential Manager នឹងបើក browser ឲ្យអ្នក Sign in ជាមួយ GitHub។ GitHub លែងទទួលលេខសម្ងាត់ធម្មតាសម្រាប់ push ហើយ — ត្រូវប្រើការចូលតាម browser, Personal Access Token ឬ SSH key។
💡 ជម្រើសងាយ៖ មិនចូលចិត្ត Terminal? GitHub Desktop (desktop.github.com) និងផ្ទាំង Source Control ក្នុង VS Code (Ctrl+Shift+G) ធ្វើបានទាំងអស់ដោយចុចប៊ូតុង។ ប៉ុន្តែគួររៀន command ជាមុន ព្រោះស្រួលយល់ជាង។
⚠️ អ្នកប្រើ Windows៖ សូមវាយ command ក្នុង Git Bash (ឬកំណត់ Terminal របស់ VS Code ជា Git Bash)។ ក្នុង Windows PowerShell 5 ពាក្យបញ្ជា echo "..." > file បង្កើត File ជា UTF-16 ដែល Git មើលឃើញជា Binary ហើយ .gitignore អាចលែងដំណើរការ។ បើ Git បើក editor Vim ដោយមិនដឹងខ្លួន៖ ចុច Esc វាយ :wq ហើយ Enter ដើម្បីរក្សាទុក និងចេញ។

⚠️ ច្បាប់មាស៖ កុំប្រើ reset --hard ឬ push --force លើ branch ដែលអ្នកដទៃប្រើរួម។ បើមិនប្រាកដ សួរមុន ឬប្រើ git revert។ បើបាន commit លេខសម្ងាត់ឡើង GitHub រួច ត្រូវ ប្តូរលេខសម្ងាត់នោះភ្លាម (ការលុបចេញពី commit មិនគ្រប់គ្រាន់ទេ)។

មេរៀន ៥Branch និង Merge

Branch ឲ្យអ្នកសាកល្បង feature ថ្មីដោយមិនប៉ះពាល់ main។ ពេលចប់ ទើបបញ្ចូលត្រឡប់មកវិញ។

💡 Fast-forward ឬ Merge commit? បើ main មិនមាន commit ថ្មីចាប់តាំងពីបង្កើត branch, Git គ្រាន់តែរំកិល main ទៅមុខ (Fast-forward)។ បើ main មាន commit ថ្មីដែរ (ដូចក្នុងរូបខាងលើ) Git បង្កើត Merge commit ថ្មី ហើយបើក editor ឱ្យសរសេរសារ។

⚔️ Merge Conflict (ជម្លោះ)

កើតឡើងពេល ២ branch កែបន្ទាត់តែមួយខុសគ្នា។ Git នឹងសួរអ្នកឲ្យជ្រើស៖

  1. បើក file ក្នុង VS Code — វាបង្ហាញប៊ូតុង Accept Current / Accept Incoming / Accept Both
  2. ជ្រើស (ឬកែដោយដៃ) ហើយលុបសញ្ញា <<<<<<<, =======, >>>>>>> ចេញ
  3. រត់ git add index.html រួច git commit ដើម្បីបញ្ចប់ merge
💡 ចង់បោះបង់ merge? វាយ git merge --abort ដើម្បីត្រឡប់ទៅមុនពេល merge។

មេរៀន ៦GitHub: ភ្ជាប់ Remote, push, pull, clone

ដាក់ project ចូល GitHub (ជំហានដំបូង)

  1. ចូល GitHub → ចុច + → New repository → ដាក់ឈ្មោះ (ឧ. my-site) → ជ្រើស Public/Private → កុំធីក "Add README" (ព្រោះយើងមាន repo ក្នុងម៉ាស៊ីនរួចហើយ) → Create repository
  2. GitHub បង្ហាញ URL របស់ repo (ឧ. https://github.com/USERNAME/my-site.git) → copy វា
  3. រត់ command ខាងក្រោមក្នុង folder គម្រោង

ពាក្យបញ្ជាសំខាន់ៗជាមួយ Remote

Commandការងារ
git clone <url>ចម្លង repo ពី GitHub មកម៉ាស៊ីន
git pushផ្ញើ commit ទៅ GitHub
git pullទាញការផ្លាស់ប្តូរពី GitHub (fetch + merge)
git fetchទាញព័ត៌មានថ្មី តែមិនទាន់ merge
git remote -vមើល remote ដែលភ្ជាប់

🔁 ទម្លាប់ប្រចាំថ្ងៃ៖ git pull → កែ code → git add . → git commit -m "..." → git push។

មេរៀន ៧ធ្វើការជាក្រុម: Fork, Pull Request, Issues

🔀 Pull Request (PR)

  1. បង្កើត branch ថ្មី៖ git switch -c fix/navbar
  2. កែ code ហើយ commit៖ git add . && git commit -m "កែ navbar លើទូរស័ព្ទ"
  3. Push branch៖ git push -u origin fix/navbar
  4. នៅ GitHub ចុចប៊ូតុង Compare & pull request → សរសេរចំណងជើង និងការពន្យល់ → Create pull request
  5. សមាជិកក្រុមពិនិត្យ (review) និងបញ្ចេញមតិ → ពេលយល់ព្រម ចុច Merge pull request
  6. ត្រឡប់ក្នុងម៉ាស៊ីន៖ git switch main && git pull

🍴 Contribute ទៅ project អ្នកដទៃ (Open Source)

  1. ចុច Fork លើ repo របស់គេ → ទទួលបានច្បាប់ចម្លងក្នុងគណនីអ្នក
  2. git clone fork របស់អ្នក → បង្កើត branch → កែ → push
  3. បើក Pull Request ពី fork ទៅ repo ដើម
  4. រក្សា fork ឱ្យទាន់សម័យ៖ git remote add upstream <url-repo-ដើម> រួច git fetch upstream និង git merge upstream/main (ឬចុច Sync fork លើ GitHub)
ឧបករណ៍ GitHubប្រើសម្រាប់
Issuesកត់ត្រា bug, គំនិត, ការងារត្រូវធ្វើ
Projectsក្តារ Kanban គ្រប់គ្រងការងារ

Releasesចេញជំនាន់ផលិតផល (v1.0.0)
Discussions / Wikiពិភាក្សា និងឯកសារ

📄 README.md — មុខមាត់នៃ repo

សរសេរដោយ Markdown។ គួរមាន៖ ឈ្មោះគម្រោង, ការពន្យល់ខ្លី, រូបថត/demo, របៀបដំឡើង និងប្រើ, ព័ត៌មានអ្នកបង្កើត។

មេរៀន ៨GitHub Pages — ដាក់ Web ឲ្យអ្នកដទៃមើល (ឥតគិតថ្លៃ)

GitHub Pages ដាក់ គេហទំព័រ static (HTML/CSS/JS) ឲ្យមានអាសយដ្ឋានពិតប្រាកដ ដូចជា https://USERNAME.github.io/my-site/។ ល្អសម្រាប់ដាក់ Portfolio និងគម្រោងដែលបានរៀនក្នុងមេរៀន CSS/JavaScript។

  1. ត្រូវប្រាកដថា repo មាន file index.html នៅ root ហើយបាន push ឡើង GitHub (មេរៀនទី ៦)
  2. នៅលើ GitHub ចូលទៅ repo → tab Settings → ជ្រើស Pages នៅម៉ឺនុយខាងឆ្វេង
  3. ក្នុងផ្នែក Build and deployment → Source ជ្រើស Deploy from a branch
  4. ជ្រើស branch main និង folder / (root) → ចុច Save
  5. រង់ចាំ ១-២ នាទី (មើលដំណើរការក្នុង tab Actions) រួចទៅ URL ដែលបង្ហាញលើទំព័រ Pages
  6. ពេលកែ code ក្រោយមក គ្រាន់តែ git push — ទំព័រនឹងធ្វើបច្ចុប្បន្នភាពស្វ័យប្រវត្តិ
🎁 គន្លឹះ Portfolio៖ បង្កើត repo ឈ្មោះ USERNAME.github.io (ជំនួស USERNAME ដោយឈ្មោះគណនីអ្នកពិតប្រាកដ) នោះ URL ដែលបានគឺ https://USERNAME.github.io ខ្លីល្អ។
⚠️ ត្រូវដឹង៖ (១) ឈ្មោះ file/folder ប្រកាន់អក្សរធំតូច — Style.css ≠ style.css នៅលើ server។ (២) ប្រើផ្លូវទាក់ទង ឧ. href="style.css" មិនមែន C:\Users\...។ (៣) repo Public ទើបប្រើ Pages ឥតគិតថ្លៃបានជាសាធារណៈ ហើយមនុស្សគ្រប់គ្នាមើល code បាន — កុំដាក់ទិន្នន័យឯកជន។ (៤) GitHub Pages មិនអាចដំណើរការ server code (Node/PHP) បានទេ។

បើចង់ដាក់ web ជាមួយ Backend ឬ framework ស្មុគស្មាញ អាចរៀនបន្ត Netlify, Vercel, Cloudflare Pages ដែលភ្ជាប់ជាមួយ GitHub ដូចគ្នា។

មេរៀន ៩ប្រើ Git ក្នុង VS Code

  1. បើក folder គម្រោង (File → Open Folder)
  2. ចុចរូប Source Control ខាងឆ្វេង (Ctrl+Shift+G)។ បើមិនទាន់មាន repo ចុច Initialize Repository
  3. file ដែលបានកែបង្ហាញក្នុងបញ្ជី — ចុច file ដើម្បីមើល diff (ខៀវ/បៃតង = បន្ថែម, ក្រហម = លុប)
  4. ចុច ＋ ក្បែរ file ដើម្បី stage (ដូច git add)
  5. វាយសារក្នុងប្រអប់ Message ហើយចុច Commit (Ctrl+Enter)
  6. ចុច Sync Changes / Publish Branch ដើម្បី push (ពេលដំបូង VS Code នឹងស្នើឲ្យ Sign in GitHub)

📝 ធ្វើលើកុំព្យូទ័រអ្នកពិតប្រាកដ។ ចុច "មើលចម្លើយ" ដើម្បីប្រៀបធៀប។

✍️ លំហាត់ ២ — Commit ដំបូង ងាយ

មើលចម្លើយ

✍️ លំហាត់ ៣ — ប្រវត្តិច្រើន commit ងាយ

✍️ លំហាត់ ៤ — .gitignore មធ្យម

មើលចម្លើយ

✍️ លំហាត់ ៥ — Branch មធ្យម

បង្កើត branch feature/about បន្ថែម about.html ហើយ merge ចូល main។

មើលចម្លើយ

🏆 ផ្នែកទី ៣: Git & GitHub កម្រិតអាជីព

របៀបដែលក្រុមអ្នកអភិវឌ្ឍន៍ពិតប្រាកដធ្វើការ៖ GitHub Flow, ការពារ Branch, SSH Key, PR/Issue Templates, GitHub Actions (CI និង Deploy Pages ស្វ័យប្រវត្តិ), Rebase, Tag/Release និងការសង្គ្រោះពេលមានបញ្ហា (reflog, bisect)។

✔ សាកល្បងរួច Command ទាំងអស់ក្នុងផ្នែកនេះ ត្រូវបានរត់សាកក្នុង Repository ពិត។

🔄 GitHub Flow — Workflow របស់ក្រុម

  1. main ត្រូវតែដំណើរការបានជានិច្ច — មិន Push ផ្ទាល់ទៅ main
  2. ការងារថ្មីនីមួយៗ = Branch ថ្មី៖ feat/login, fix/navbar
  3. Commit តូចៗ ញឹកញាប់ ជាមួយសារ Conventional Commits
  4. Push ហើយបើក Pull Request → CI រត់ Test ស្វ័យប្រវត្តិ
  5. សមាជិកម្នាក់ទៀត Review → Approve
  6. Merge → Deploy ស្វ័យប្រវត្តិ → លុប Branch

ការពារ Branch main (Rulesets)

GitHub → repo → Settings → Rules → Rulesets → New branch ruleset → Target: main → ធីក៖

  • ✅ Require a pull request before merging (+ ១ approval)
  • ✅ Require status checks to pass (ជ្រើស Job test ពី CI)
  • ✅ Block force pushes និង Restrict deletions

🔑 SSH Key — ចូល GitHub ដោយមិនវាយលេខសម្ងាត់

📁 File ស្តង់ដាររបស់ Repository អាជីព

1) CI — រត់ Test រាល់ Pull Request

2) Deploy GitHub Pages ដោយ Actions

ល្អជាង «Deploy from a branch» ពេល Project ត្រូវ Build មុន (ឧ. Vite → dist/)។ កំណត់ Settings → Pages → Source: GitHub Actions។

3) Templates សម្រាប់ PR និង Issue

4) .gitattributes — ការពារបញ្ហាចុងបន្ទាត់ Windows/Mac

🛠️ Command កម្រិតខ្ពស់

Rebase — ធ្វើឱ្យប្រវត្តិស្អាតមុនបើក PR

⚠️ ច្បាប់៖ Rebase តែ Branch ផ្ទាល់ខ្លួនដែលគ្មានអ្នកដទៃប្រើប៉ុណ្ណោះ — កុំ Rebase main។

Tag & Release — ចេញ Version

Semantic Versioning MAJOR.MINOR.PATCH៖ PATCH = កែ Bug · MINOR = មុខងារថ្មី · MAJOR = ប្តូរធំដែលខូចភាពត្រូវគ្នា។

សង្គ្រោះ និងរក Bug

🏁 លំហាត់គម្រោងចុងក្រោយ

  1. បង្កើត SSH key ហើយប្តូរ Portfolio repo ទៅប្រើ SSH
  2. បន្ថែម .github/ (CI, PR template, Issue template) ទៅ repo
  3. បង្កើត Ruleset ការពារ main ហើយសាក Push ផ្ទាល់ (ត្រូវតែបរាជ័យ)
  4. ធ្វើការកែតាម Branch + Pull Request ហើយមើល CI រត់
