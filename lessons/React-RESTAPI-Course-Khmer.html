១. React និង REST API ជាអ្វី? អ្នកណាបង្កើត?

API (Application Programming Interface)
«ច្រកទ្វារ» ដែលកម្មវិធីមួយប្រើដើម្បីសុំទិន្នន័យ ឬសេវាពីកម្មវិធីមួយទៀត។ ដូចអ្នករត់តុក្នុងភោជនីយដ្ឋាន៖ អ្នក (Client) កុម្ម៉ង់ → អ្នករត់តុ (API) → ផ្ទះបាយ (Server/Database)។
REST (REpresentational State Transfer)
របៀបរចនា API លើ HTTP៖ ទិន្នន័យជា Resource (/products) ហើយប្រើ Method (GET, POST, PATCH, DELETE) ផ្ញើ/ទទួលជា JSON។
React
បណ្ណាល័យ JavaScript សម្រាប់បង្កើត User Interface ពី Components ដែលប្រើឡើងវិញបាន ហើយ UI ធ្វើបច្ចុប្បន្នភាពដោយខ្លួនឯងពេល State ប្តូរ។

មេរៀន ៤Middleware, Validation (Zod) & Error Handling

Middleware = (req, res, next) => {…} រត់តាមលំដាប់ មុនដល់ Route។ ហៅ next() ដើម្បីបន្ត ឬ next(err) ដើម្បីទៅ Error handler។

💡 ទម្រង់ Error តែមួយ ទូទាំង API ({ error: { message, details? } }) ជួយឱ្យ React បង្ហាញ Error បានងាយ។ កុំបញ្ចេញ Stack trace ឬសារ Database ទៅ Client។

✍️ លំហាត់ ៤

សរសេរ Zod schema សម្រាប់ register៖ name (2–50 តួ), email, password (≥ 8 តួ មានលេខយ៉ាងតិច 1), phone (ចាប់ផ្តើម 0, 9–10 ខ្ទង់, optional)។

មេរៀន ៥Database: SQLite + SQL ក្នុង API

Node.js 22.13+ មាន node:sqlite ស្រាប់ (មិនចាំបាច់ npm install)។ គម្រោងធំប្រើ PostgreSQL/MySQL ជាមួយ ORM ដូចជា Prisma ឬ Drizzle — គំនិតដូចគ្នា។

⚠️ SQL Injection៖ កុំភ្ជាប់ String ចូល SQL ផ្ទាល់ `... WHERE name = '${req.query.name}'` — ប្រើ ? (Prepared statement) ជានិច្ច។

✍️ លំហាត់ ៥

សរសេរ Route GET /api/stats ដែលត្រឡប់ចំនួនផលិតផល តម្លៃមធ្យម និងចំនួនដែលអស់ស្តុក តាមប្រភេទនីមួយៗ។

មើលចម្លើយ

មេរៀន ៦Authentication: bcrypt + JWT

  1. Register៖ រក្សាទុក hash នៃពាក្យសម្ងាត់ (bcrypt) — កុំរក្សាពាក្យសម្ងាត់ដើម
  2. Login៖ ពិនិត្យ hash → បង្កើត JWT (JSON Web Token) ដែលមាន id/role ហើយចុះហត្ថលេខាដោយ JWT_SECRET
  3. Client៖ ផ្ញើ Authorization: Bearer <token> ជាមួយ Request ដែលត្រូវការសិទ្ធិ
  4. Middleware៖ ផ្ទៀងផ្ទាត់ Token → req.user · ពិនិត្យ Role (401 vs 403)

✍️ លំហាត់ ៦

សរសេរ POST /api/auth/register ដែល hash ពាក្យសម្ងាត់ ហើយត្រឡប់ 409 បើអ៊ីមែលមានរួច។

មើលចម្លើយ

មេរៀន ១៤កម្រិតខ្ពស់: TanStack Query, Env, Build & Deploy

  • TanStack Query៖ Cache, Refetch, Retry, Pagination ដោយស្វ័យប្រវត្តិ — ជំនួស useEffect+fetch ក្នុងគម្រោងធំ
  • Environment variables (Vite)៖ client/.env → VITE_API_URL=https://api.kafe.com → import.meta.env.VITE_API_URL (មានតែ Prefix VITE_ ប៉ុណ្ណោះដែលចូល Browser — កុំដាក់ Secret!)
  • Build៖ npm run build → Folder dist/ (HTML/CSS/JS ស្តាទិក)
  • Deploy៖ Frontend → Vercel / Netlify / Cloudflare Pages · Backend → Render / Railway / Fly.io / VPS (PM2 + Nginx)
  • Security Token៖ គម្រោងពិតគួររក្សា Token ក្នុង httpOnly cookie (ការពារ XSS) ឬ Memory + Refresh token

✍️ លំហាត់ ១៤

Deploy រួច Frontend (https://kafe.vercel.app) ហៅ API (https://kafe-api.onrender.com) ហើយ Browser បង្ហាញ «blocked by CORS policy»។ កែដូចម្តេច?

មើលចម្លើយ

ខាង Server (មិនមែន React)៖ កំណត់ CLIENT_URL=https://kafe.vercel.app ក្នុង Environment របស់ Render ហើយ app.use(cors({ origin: process.env.CLIENT_URL }))។ ខាង Client៖ VITE_API_URL=https://kafe-api.onrender.com/api ហើយ Build ឡើងវិញ។ CORS ជាច្បាប់របស់ Browser — Server ត្រូវប្រាប់ថាអនុញ្ញាត Origin ណា។
