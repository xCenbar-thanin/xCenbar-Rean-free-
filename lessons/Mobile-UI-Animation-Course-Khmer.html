១. ហេតុអ្វី Animation សំខាន់?

មេរៀន ១Duration & គោលការណ៍ Motion

ប្រភេទDuration ណែនាំឧទាហរណ៍
តូច (Icon, Switch, Ripple)100–200ms❤️ Like, Checkbox
មធ្យម (Card ពង្រីក, Dialog)200–300msBottom sheet
ធំ (ប្តូរអេក្រង់)300–500msHero transition
ចេញ (Exit)លឿនជាងចូល ~20–30%Dialog បិទ
🧩 របៀប Code ជំហានៗ
  1. ចលនាក្នុងពិភពពិត មិនដែលល្បឿនថេរ (linear) — វាចាប់ផ្តើមយឺត លឿន ហើយយឺតវិញ (Ease)។ សាកប្រៀបធៀប ៣ ប្រអប់ក្នុង Demo។
  2. Duration ខ្លីពេក → អ្នកប្រើមើលមិនទាន់ · វែងពេក → App ហាក់ដូចយឺត (រំខានពេលប្រើញឹកញាប់)។
  3. ទំហំធំ/ចម្ងាយឆ្ងាយ → Duration វែងបន្តិច · វត្ថុតូច → ខ្លី។
  4. គោលការណ៍ Disney ដែលប្រើញឹកញាប់ក្នុង UI៖ Ease in/out, Anticipation (ថយក្រោយបន្តិចមុនលោត), Follow-through (លើសបន្តិចហើយត្រឡប់ — Overshoot), Squash & stretch។
  5. Animation មានគោលបំណង៖ សួរខ្លួនឯងថា "វាជួយអ្នកប្រើយល់អ្វី?" — បើគ្មាន កុំ Animate។

ease-out        0%   31%   57%   79%   94%  100%
emphasized      0%   50%   80%   93%   98%  100%

🧩 របៀប Code ជំហានៗ
  1. Cubic Bézier មានចំណុចបញ្ជា ២ (x1,y1) (x2,y2) · x = ពេលវេលា · y = ភាពរីកចម្រើន (progress)។
  2. លទ្ធផលពិត៖ នៅ 20% នៃពេល emphasized ទៅដល់ 50% · ease-out 31% · linear ត្រឹម 20% → ខ្សែកោងចាប់ផ្តើមលឿន មានអារម្មណ៍ឆ្លើយតបភ្លាម។
  3. y > 1 (ឧ. 1.56) → Overshoot (ទៅហួស ~10% ហើយត្រឡប់) — ល្អសម្រាប់ Icon/Badge លេចឡើង។
  4. ចូលអេក្រង់ → ease-out (decelerate) · ចេញ → ease-in (accelerate) · ផ្លាស់ក្នុងអេក្រង់ → ease-in-out។
  5. សាករចនាខ្សែកោងផ្ទាល់ (អូសចំណុច) ក្នុង Motion Lab Pro → Easing editor។

មេរៀន ៣Spring Physics

លទ្ធផលពិត · Python 3
bouncy (ζ=0.3)         ζ=0.30 overshoot= 36.8%  settle(±1%)= 808ms
smooth (ζ=0.7)         ζ=0.70 overshoot=  3.9%  settle(±1%)= 362ms
critical (ζ=1.0)       ζ=1.00 overshoot=  0.0%  settle(±1%)= 392ms
stiff (k=800, ζ=0.8)   ζ=0.80 overshoot=  0.7%  settle(±1%)= 138ms
🧩 របៀប Code ជំហានៗ
  1. Spring = ផ្ទាំងរ៉ឺស័រ៖ stiffness (k) ខ្លាំង = លឿន · damping (c) = កម្លាំងបន្ថយ · mass = ធ្ងន់។
  2. Damping ratio ζ = c / (2√(k·m))៖ ζ < 1 លោត (Bouncy) · ζ = 1 មិនលោតលឿនបំផុត (Critical) · ζ > 1 យឺត។
  3. លទ្ធផលពិត៖ ζ=0.3 លើស ~37% · ζ=0.7 លើសតែ ~4% (ល្អសម្រាប់ UI ភាគច្រើន) · ζ=1 គ្មានលើស។
  4. Spring គ្មាន Duration ថេរ — វាឆ្លើយតបនឹង Velocity (ឧ. អូសលឿនហើយលែង) និងអាចរំខានពាក់កណ្តាលបានរលូន → ល្អសម្រាប់ Gesture។
  5. Apple ប្រើ Spring ជាលំនាំដើម (iOS 17+) · សាកកែ k/c/m ក្នុង Motion Lab Pro → Spring។

មេរៀន ៥Explicit Animation, Sequence & Stagger

🧩 របៀប Code ជំហានៗ
  1. Explicit — គ្រប់គ្រង Animation ផ្ទាល់៖ ចាប់ផ្តើម/ឈប់/ថយក្រោយ/ធ្វើម្តងទៀត (AnimationController, Animatable)។
  2. Stagger — ធាតុនីមួយៗចាប់ផ្តើមយឺតជាងមុន 30–80ms → ភ្នែកតាមដានលំដាប់បាន (Demo)។ កុំ Stagger លើស ~8 ធាតុ (យឺតពេក)។
  3. Interval(start, end) (Flutter) — ចែកពេល Controller មួយឲ្យធាតុច្រើន។
  4. Sequence៖ animateTo បន្តគ្នាក្នុង Coroutine (Compose) · withSequence (Reanimated) · PhaseAnimator (SwiftUI)។
  5. Flutter៖ ត្រូវ dispose() Controller ជានិច្ច (ការពារ Memory leak)។

  4. Tag/ID ត្រូវ មិនស្ទួន ក្នុងអេក្រង់ (ប្រើ id ទំនិញ)។

Grid មាន Iced Latte ២ (Hot/Iced) ដែលមានរូបដូចគ្នា។ Hero tag ប្រើអ្វី?

មើលចម្លើយ

ប្រើ id មិនស្ទួន (product-12, product-13) មិនមែនឈ្មោះ ឬ URL រូបភាព — tag ស្ទួន = Error/Animation ខុស។

មេរៀន ៧Gesture-driven Animation៖ Bottom Sheet

🧩 របៀប Code ជំហានៗ
  1. Gesture-driven៖ ពេលអូស → វត្ថុតាមម្រាមដៃ ១:១ (គ្មាន Animation) · ពេលលែង → Animation ពី ទីតាំង + Velocity បច្ចុប្បន្ន។
  2. Velocity projection៖ ទាយទីតាំងបញ្ចប់ y + v × 0.15 → ជ្រើស Snap point ជិតបំផុត (Fling លឿនទៅឆ្ងាយ)។
  3. Spring ទទួល Velocity ដំបូង → បន្តចលនារលូនពីម្រាមដៃ (Timing animation ធ្វើមិនបាន)។
  4. Rubber banding — អូសហួសដែនកំណត់ → ផ្លាស់តែ 30% (ដូច iOS scroll)។
  5. Production៖ Compose AnchoredDraggable · SwiftUI presentationDetents · Flutter DraggableScrollableSheet · RN Gesture handler + Reanimated។

✍️ លំហាត់ ៧

Swipe-to-dismiss Card៖ លែងពេលណាគួរលុប?

មើលចម្លើយ

លុបពេល អូសលើស ~40% ទទឹង ឬ Velocity > ~800 px/s (Fling) · ផ្សេងពីនេះ Spring ត្រឡប់ទៅកន្លែងដើម។

មេរៀន ៨Micro-interactions

🧩 របៀប Code ជំហានៗ
  1. Micro-interaction = Trigger (ចុច) → Feedback (រួមតូច/ពង្រីក/Burst/Vibration) → ស្ថានភាពថ្មី (♥ · Badge +1)។
  2. Press state៖ scale 0.92–0.96 ពេលចុច → ប៊ូតុងមានអារម្មណ៍ "ចុចបាន"។
  3. Add to cart fly — វត្ថុហោះទៅកន្ត្រក (Keyframes ៣ ចំណុច) + Badge កើន + កន្ត្រករញ្ជួយ → អ្នកប្រើដឹងច្បាស់ថាបានបន្ថែម។
  4. Haptics (Vibration ស្រាល) — iOS .sensoryFeedback · Flutter HapticFeedback · Android performHapticFeedback។
  5. កុំបន្ថែមលើសលប់ — Micro-interaction ល្អគឺ "មានអារម្មណ៍" ប៉ុន្តែស្ទើរតែមិនកត់សម្គាល់។

✍️ លំហាត់ ៨

មើលចម្លើយ
