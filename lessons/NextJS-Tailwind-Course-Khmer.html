២. របៀបដំឡើងក្នុង VS Code

  1. ដំឡើង Node.js LTS (Next.js 16 ត្រូវការ Node 20.9+) ពី nodejs.org
  2. បើក VS Code → Terminal (Ctrl+`) ហើយរត់ npx create-next-app@latest
  3. ឆ្លើយសំណួរ៖ TypeScript Yes · ESLint Yes · Tailwind CSS Yes · src/ តាមចិត្ត · App Router Yes · Turbopack Yes · Import alias @/*
  4. Extensions៖ Tailwind CSS IntelliSense (Autocomplete class + មើល CSS ពេលដាក់ Mouse) · ESLint · Prettier (+ prettier-plugin-tailwindcss តម្រៀប Class ដោយស្វ័យប្រវត្តិ)
  5. រត់ npm run dev ហើយបើក http://localhost:3000
💡 Tailwind v4 មិនត្រូវការ tailwind.config.js ទៀតទេ — ការកំណត់ទាំងអស់នៅក្នុង CSS (@theme)។ វារកឃើញឯកសារ Source ដោយស្វ័យប្រវត្តិ។

មេរៀន ៧ Server Components vs Client Components

រាល់ Component ក្នុង app/ ជា Server Component តាម Default៖ វារត់នៅ Server, អាច await Database ផ្ទាល់, អាចប្រើ Secret keys ហើយ JavaScript របស់វាមិនទៅ Browser។ ពេលត្រូវការ Interactivity (useState, onClick) បន្ថែម 'use client' នៅលើឯកសារ។

ត្រូវការ...Server ✅Client ✅
ទាញទិន្នន័យពី DB / API ដោយ Secret✔✘
useState, useEffect, onClick, onChange✘✔
localStorage, window, Geolocation✘✔
កាត់បន្ថយ JS ក្នុង Browser✔—
💡 ច្បាប់៖ ដាក់ 'use client' ឱ្យ ទាបបំផុត ក្នុង Tree (Leaf components)។ Props ពី Server → Client ត្រូវ Serialize បាន (string, number, object, Date, Promise) — មិនអាចផ្ញើ Function ធម្មតាទេ (លើកលែង Server Action)។ Server Component អាចជា children របស់ Client Component។
⚠️ កុំ import ឯកសារដែលមាន Secret ក្នុង Client Component។ ដាក់ import "server-only"; នៅលើ lib/db.ts — Build នឹងបរាជ័យបើវាត្រូវបាន import ទៅ Client ដោយច្រឡំ។

Component ខាងក្រោមមានកំហុស។ ពន្យល់ ហើយកែ៖ export default async function Like() { const [n, setN] = useState(0); const post = await db.post.findFirst(); ... }

⚠️ Server Action ជា Public endpoint — អ្នកណាក៏អាចហៅវាបាន (មិនមែនតែ Form របស់អ្នក)។ ត្រូវ Validate input (Zod) និង ពិនិត្យ Auth/សិទ្ធិ ក្នុង Action នីមួយៗ ដូចការពារ API ដែរ។

សរសេរ Server Action deleteProduct(id: number) ដែលពិនិត្យ Admin, លុប, ហើយ Invalidate Cache។ ហៅវាពីប៊ូតុងក្នុង Server Component។

មេរៀន ១១ Route Handlers (REST API) & proxy.ts

ត្រូវការ API សម្រាប់ Mobile app, Webhook ឬ Client ខាងក្រៅ? បង្កើត route.ts ហើយ Export Function តាម HTTP method។ ប្រើ Web standard Request/Response។

proxy.ts (ពីមុនហៅ middleware.ts)

ចាប់ពី Next.js 16 middleware.ts ត្រូវបានប្តូរឈ្មោះជា proxy.ts (Function proxy)។ វារត់ មុន Route — ល្អសម្រាប់ Redirect លឿនៗ (ឧ. មិនទាន់ Login), i18n, Headers។

💡 Proxy ជា ការពិនិត្យលឿន (Optimistic) ប៉ុណ្ណោះ — ត្រូវពិនិត្យ Session ពិតម្តងទៀត ក្នុង Server Component/Action/Route ដែលចូលប្រើទិន្នន័យ (ការពារ Bypass)។

✍️ លំហាត់ ១១

បង្កើត GET /api/health ដែលឆ្លើយ { ok: true, time: ... } ហើយមិន Cache។

មើលចម្លើយ

Route Handlers ជា Dynamic តាម Default (មិន Cache) លុះត្រាតែប្រើ 'use cache' ក្នុង Function ដែលវាហៅ។

មេរៀន ១៤ Build & Deploy (Vercel, Docker)

ℹ️ លទ្ធផលខាងលើជា ឧទាហរណ៍ (មិនមែនរត់ពិតក្នុងវគ្គនេះ) — និមិត្តសញ្ញាពិតអាចខុសបន្តិចតាមកំណែ។

Deploy ទៅ Vercel (ងាយបំផុត)

  1. Push កូដទៅ GitHub
  2. vercel.com → Add New Project → Import repo (ស្គាល់ Next.js ស្វ័យប្រវត្តិ)
  3. បញ្ចូល Environment Variables (DATABASE_URL, SESSION_SECRET)
  4. Deploy → រាល់ Push ទៅ main = Production, រាល់ PR = Preview URL
