១. ការទូទាត់ឌីជីថលនៅកម្ពុជា៖ Bakong & KHQR

Bakong គឺជាប្រព័ន្ធទូទាត់ជាតិរបស់ ធនាគារជាតិនៃកម្ពុជា (NBC) ដែលដាក់ឲ្យប្រើជាផ្លូវការនៅខែតុលា ឆ្នាំ 2020 ដោយប្រើបច្ចេកវិទ្យា Blockchain Hyperledger Iroha (សហការជាមួយក្រុមហ៊ុន Soramitsu ប្រទេសជប៉ុន)។ KHQR គឺជា ស្តង់ដារ QR តែមួយ (ផ្អែកលើ EMVCo Merchant-Presented QR) ដែលធ្វើឲ្យ App ធនាគារណាក៏ស្កេនបង់ទៅគណនីធនាគារណាក៏បាន ជាប្រាក់ រៀល (KHR) ឬ ដុល្លារ (USD)។

🧩 របៀប Code ជំហានៗ
  1. CRC16-CCITT (Polynomial 0x1021, Initial 0xFFFF) — គណនាលើ String ទាំងមូល រួមទាំង "6304" ហើយដាក់លទ្ធផល ៤ Hex នៅចុង។
  2. កែតួអក្សរតែ ១ → CRC ប្តូរ → App ធនាគារដឹងថា QR ខូច/ត្រូវគេកែ (លទ្ធផលពិតខាងលើ)។
  3. CRC មិនមែនជាការការពារសុវត្ថិភាព (អ្នកក្លែងអាចគណនា CRC ថ្មីបាន) — វាការពារតែកំហុសស្កេន/វាយ។ សុវត្ថិភាពពិតគឺ Backend ផ្ទៀងផ្ទាត់តាម API (មេរៀន ៩)។
  4. MD5 នៃ KHQR String ទាំងមូល = លេខសម្គាល់ QR នោះ → Backend ប្រើសួរ Bakong ថា "QR នេះត្រូវបានបង់ហើយឬនៅ?"។
  5. Python និង JavaScript ឲ្យលទ្ធផលដូចគ្នា 16C4 ✓

  2. Gateway នីមួយៗកំណត់ លំដាប់ Field និង Algorithm ផ្ទាល់ (ឧ. PayWay ប្រើ HMAC-SHA512 + Base64) — អនុវត្តតាម Docs ផ្លូវការត្រឹមត្រូវ។
  3. Webhook = Gateway ហៅ URL របស់អ្នកពេលបង់រួច (មិនបាច់ Polling) — ត្រូវផ្ទៀងផ្ទាត់ Signature និង ពិនិត្យ Status តាម API ម្តងទៀត។
  4. hmac.compare_digest — ប្រៀបធៀបដោយពេលថេរ (ការពារ Timing attack)។
  5. លទ្ធផលពិត៖ Webhook ដែលត្រូវគេកែ amount → Signature មិនត្រូវ → បដិសេធ។

✍️ លំហាត់ ១០

Webhook URL របស់អ្នកត្រូវបានគេដឹង ហើយគេផ្ញើ "PAID" ក្លែង។ ការពារដោយអ្វីខ្លះ?

មើលចម្លើយ

① ផ្ទៀងផ្ទាត់ Signature · ② ពិនិត្យ Status តាម API របស់ Gateway ម្តងទៀត · ③ ផ្ទៀងផ្ទាត់ amount/currency/order · ④ Idempotent · ⑤ HTTPS + (បើមាន) IP allowlist។
