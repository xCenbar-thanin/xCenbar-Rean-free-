១. Backend ជាអ្វី? Firebase & Supabase

App ស្ទើរតែទាំងអស់ត្រូវការ Backend៖ កន្លែងរក្សា គណនីអ្នកប្រើ, ទិន្នន័យ (Menu, Order), រូបភាព និង Code ដែលរត់លើ Server។ ជំនួសឲ្យការសរសេរ Server ខ្លួនឯង យើងអាចប្រើ BaaS (Backend-as-a-Service) ដូចជា Firebase និង Supabase ដែលភ្ជាប់បានជាមួយ Flutter, React Native, Kotlin និង Swift (វគ្គមុនៗ)។

មេរៀន ១Backend, REST API & JSON

App និយាយជាមួយ Backend តាម HTTP៖ ផ្ញើ Request (GET/POST/PATCH/DELETE) ហើយទទួល Response ជា JSON។ Code ខាងក្រោមបង្កើត Server តូចមួយ ហើយហៅវាពិតៗដោយ Node.js៖

លទ្ធផលពិត · Node.js
GET /menu → 200 [
  { id: 1, name: 'Latte', price: 2.5 },
  { id: 2, name: 'Mocha', price: 2.75 }
]
POST /orders → 201 { id: 1, item: 'Latte', qty: 2, total: 5, status: 'pending' }
POST bad → 400 { error: 'ទិន្នន័យមិនត្រឹមត្រូវ' }
🧩 របៀប Code ជំហានៗ
  1. http.createServer — Server ទទួល Request · req.method + req.url = ផ្លូវ (Route)។
  2. Status code៖ 200 OK · 201 Created · 400 ទិន្នន័យខុស · 401 មិនទាន់ Login · 403 គ្មានសិទ្ធិ · 404 រកមិនឃើញ · 500 Server error។
  3. JSON.stringify / JSON.parse — Object ↔ អក្សរ JSON ដែលធ្វើដំណើរលើ Network។
  4. Server ត្រួតពិនិត្យ ទិន្នន័យ (item មាន, qty ≥ 1) និង គណនាតម្លៃខ្លួនឯង — កុំជឿតម្លៃពី App។
  5. Firebase/Supabase ធ្វើការងារ Server ទាំងនេះជំនួសយើង + Auth + Realtime + Scale។

🧩 របៀប Code ជំហានៗ

មេរៀន ៥Query, Realtime & Pagination

🧩 របៀប Code ជំហានៗ
  1. where តម្រង (==, !=, <, >=, in, array-contains) · orderBy តម្រៀប · limit ចំនួន។
  2. Query ច្រើនលក្ខខណ្ឌ (where + orderBy Field ផ្សេង) ត្រូវការ Composite index — Error នឹងផ្តល់ Link បង្កើតវា។

មេរៀន ៦Firestore Security Rules & Emulator

🧩 របៀប Code ជំហានៗ
  1. match /orders/{orderId} — ច្បាប់សម្រាប់ Document ក្នុង Collection · {orderId} = Wildcard។
  2. request.auth = អ្នកណាផ្ញើ (null បើមិន Login) · resource.data = ទិន្នន័យដែលមានស្រាប់ · request.resource.data = ទិន្នន័យថ្មីដែលកំពុងសរសេរ។
  3. Validation នៅក្នុង Rules៖ total is number && total > 0, keys().hasOnly([...])។
  4. Rules មិនមែនជា Filter៖ Query ត្រូវមាន where('uid','==',uid) ដែលត្រូវនឹងច្បាប់ ទើបអនុញ្ញាត។
  5. request.auth.token.admin — Custom claim កំណត់ពី Admin SDK (មេរៀន ៨)។
  6. ⚠️ Test mode (allow read, write: if true) = អ្នកណាក៏លុប Database បាន! ប្តូរមុន Launch ជានិច្ច។
